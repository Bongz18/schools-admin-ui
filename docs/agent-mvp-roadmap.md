# School Admin AI MVP Roadmap

## Goal
Build a functional school admin app where the UI is operational and AI agents support high-value admin work without taking over sensitive decisions.

## Product direction
This application should work as a secure admin dashboard for school operations with AI agents helping in specific workflows:

- application triage and summary
- parent and school record search
- document/eligibility checks
- follow-up email drafting
- workflow recommendations for staff
- anomaly detection and alerts
- report generation

The app remains the system of record. Agents are tools that assist staff, not autonomous decision-makers.

## Core architecture

### 1. Frontend
- Next.js app router
- Admin-only protected routes
- Reusable dashboard UI and forms
- Role-aware navigation

### 2. Backend and data
- Supabase Postgres for app data
- Auth for staff and admin users
- RLS rules to protect operations
- Schema for schools, applications, users, agents, actions, logs

### 3. AI / agent layer
- LLM service for summarization, recommendations, draft generation
- Tools for reading/writing records
- Structured prompts with guardrails
- Human approval checkpoint for sensitive actions

### 4. Guardrails
- admin-only permissions
- audit logs for all agent actions
- explicit approval before changing status, deleting records, or sending emails
- fallback to manual process when confidence is low

## MVP feature set

### Phase 1 — Working admin app foundation
- Admin login and route protection
- Dashboard layout
- School management page
- User management page
- Applications management page
- Read-only agent summary panel on each app

### Phase 2 — AI assistant workflows
- Summarize an application in plain English
- Flag missing required documentation
- Draft response email to parent or staff
- Recommend next status (submitted, in review, accepted, rejected)
- Detect duplicate/edge-case applications

### Phase 3 — Approval workflows
- Agent generates recommendation
- Admin reviews and clicks Approve / Reject / Edit
- Action is logged with timestamp and user

### Phase 4 — Operational automation
- Scheduled task reminders
- Weekly summary reports
- Alerts for incomplete applications
- Exportable school reports

## Recommended data model

### Tables
- users
- schools
- applications
- application_notes
- agent_runs
- agent_actions
- audit_logs

### Example fields
- users: id, email, role, full_name, created_at
- schools: id, name, location, status
- applications: id, parent_id, school_id, status, notes, created_at, updated_at
- agent_runs: id, trigger, status, prompt, result_summary, created_by
- agent_actions: id, run_id, action_type, payload, approved_by, executed_at
- audit_logs: id, entity_type, entity_id, event, actor_id, created_at

## Workflow pattern

1. User opens an application
2. Agent reads application + related school and parent records
3. Agent produces a structured recommendation
4. UI shows summary, confidence, risks, and suggested next action
5. Admin approves or edits before anything changes
6. System logs the final action

## First implementation tasks

### Task 1: Fix the app foundation
- ensure admin routes and Supabase auth are consistent
- standardize import paths
- centralize Supabase client configuration
- remove debug logs and insecure patterns

### Task 2: Add a dashboard home screen
- overview cards: schools, applications, users, pending reviews
- quick actions panel
- recent activity feed

### Task 3: Add AI review panel to applications
- button: “AI Review Application”
- call LLM with app + metadata
- show summary, risk flags, recommended next step
- keep the result as a read-only preview until approved

### Task 4: Add approval step
- draft email or status update generated by agent
- admin chooses approve / reject / edit
- write result into the application record

### Task 5: Add durable audit logging
- capture who triggered each AI recommendation
- capture timestamps and action payloads
- enable traceability for compliance and debugging

## Success criteria
The MVP is successful when:

- an admin can sign in and access protected pages
- school, user, and application records can be managed
- AI can summarize and recommend actions for an application
- actions require review before being persisted
- audit logs record who did what and when
- the app is usable for real admin workflows without hidden AI autonomy

## Recommended order of execution

1. app foundation and auth cleanup
2. dashboard and admin navigation
3. applications management improvements
4. AI review panel
5. approval workflow
6. audit logs and reporting
7. notification/email automation

## Strategic note
The best version of this product is not a fully autonomous robot admin. It is a trusted admin copilot: the system handles heavy lifting, gives recommendations, drafts outputs, and speeds up admin work while preserving accountability.

This is the right product pattern for educational operations, compliance, and staffing workflows.
